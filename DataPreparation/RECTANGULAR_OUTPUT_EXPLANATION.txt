================================================================================
DETAILED BREAKDOWN:
================================================================================

WHERE RECTANGLES COME FROM:
---------------------------
1. During data processing (convert_resplan_to_mat.py):
   - Computed as bounding boxes: polygon.bounds → (minx, miny, maxx, maxy)
   - Purpose: Simplified representation for graph neural network
   - Both 'box' AND 'rBoundary' are saved to .mat/.pkl files

2. Model uses ONLY the 'box' field:
   - Training: Loss function optimizes rectangular box predictions
   - Architecture: graph_net outputs box coordinates, not polygon vertices
   - No mechanism to predict arbitrary polygon shapes

WHERE COMPLEX SHAPES IN rBoundary COME FROM:
--------------------------------------------
1. In TRAINING data: From original ResPlan polygons
   - extract_coords_from_shapely(polygon) preserves actual room geometry
   - But model never uses these during training!

2. In GENERATED data: From post-processing of rectangles
   - get_room_boundary.m applies boolean operations on rectangles
   - intersect(boundary, rectangle) ∩ subtract(other_rectangles)
   - Creates complex shapes, but they're derived from rectangles
   - NOT the same as original training data polygons

IS IT A VISUALIZATION ISSUE?
-----------------------------
NO. The interface correctly shows what the model generates.

If you modified the interface to display rBoundary instead of box:
  • For training data: You'd see original complex shapes
  • For generated data: You'd see rectangle-derived complex shapes
  • But the MODEL still only knows how to generate rectangles

================================================================================
CONCLUSION:
================================================================================

The rectangular-only output is a FUNDAMENTAL MODEL ARCHITECTURE LIMITATION.

To generate complex room shapes, you would need to:
  1. Modify the model architecture to predict polygon vertices
  2. Change the loss function to optimize polygon shapes
  3. Retrain the entire model with rBoundary as target
  4. Potentially redesign the graph neural network structure

This is not a simple fix - it would be a research-level modification to the
Graph2Plan paper's approach.

The current design choice (rectangles) was intentional for:
  • Simplicity: 4 coordinates per room vs. variable polygon vertices
  • Network architecture: Easier to predict fixed-size outputs
  • Loss computation: MSE loss on box coordinates is straightforward
  • Alignment: Rectangular layouts are easier to regularize
